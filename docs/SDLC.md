# SDLC Control

## Lifecycle

1. **Discover** — Build Truth and lineage extraction.
2. **Define** — ontology, architecture, truth boundary and Definition of Done.
3. **Design** — graph schema, organ contracts, API, UI and evidence model.
4. **Implement** — executable model + HTTP service + visualization.
5. **Verify** — unit tests, integration tests and invariant gate.
6. **Receipt** — hash canonical model and emit `GA-MOR-SDLC-IMPLEMENTATION-001`.
7. **Integrate** — pull request and CI evidence.
8. **Deploy** — Render web service with `/health` gate.
9. **Operate** — monitor service; no physical-estate claims from web-service uptime.
10. **Promote** — only evidence-backed state may move to golden baseline.

## Definition of Done for software MVP

- 16 Build Truth files remain present.
- Original 23-organ registry remains exactly 23.
- All graph references validate.
- Source → manifestation layers exist.
- Universal Atlas / SESHAT / Thoth are distinct authorities.
- Euna is simulation-only until promotion.
- API and UI are operational.
- Tests and invariant verification pass.
- Implementation receipt is emitted.
- Public deployment health responds.

Physical EDEN, unattended second-cycle and external commercial evidence remain separate campaign gates.
