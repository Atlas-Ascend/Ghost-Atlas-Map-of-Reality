# Security and Authority

The deployed MVP is intentionally read-only. It has no credential ingestion, shell execution, repository mutation, physical-machine control, payment action or destructive endpoint.

## Promotion law

`OBSERVATION → EPISTEMIC CLASS → AUTHORITY CHECK → VERIFICATION → PROOF RECEIPT → CANONICAL PROMOTION`

## Execution law

Future mutation-capable adapters must require an Execution Envelope containing mission, packet, role, capabilities, filesystem/network/credential scope, model/node class, runtime/mutation limits, reversibility, Medusa observation, SECA verification and ProofGrid receipt requirements.

PROMETHEUS proposes. MetaForge implements. SECA judges. OSIRIS restores. JANUS authorizes.
